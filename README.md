# capp-parse

An Objective-J and Javascript source parser for the Cappuccino toolchain.
The application wraps the dynamic library generated by [tree-sitter](https://tree-sitter.github.io/tree-sitter/) using:
* [purego](https://github.com/ebitengine/purego)
* [go-tree-sitter](https://github.com/tree-sitter/go-tree-sitter)

The Objective-J grammar is distributed as a platform-specific dynamic library installed using this application.
This delivers a first-class and independently deployable artifact available for use by third-party tooling in any language.

See the separate tree-sitter-objj repository for the raw grammar.

---

## Prerequisites

The compiled grammar dynamic library must be installed and locatable. By default the following paths are searched in order:

```
/usr/local/lib/tree-sitter
/opt/local/lib/tree-sitter    (MacPorts)
~/Library/tree-sitter
/Library/tree-sitter
```

An explicit path can be supplied to any command via `--grammar`.

## Build

```sh
# Current platform
go build -o capp-parse .

# All platforms
make all

# Darwin only
make darwin

# With explicit version
make LDFLAGS='-ldflags "-X main.version=v1.0.0"'
```

Version defaults to the short git commit hash.

## Commands

### parse

Parse a file, directory tree, or stream of file paths from stdin.

```
capp-parse parse [flags] [path]

Flags:
  -g, --grammar  path    explicit grammar dylib path, overrides search
      --mode     auto | objj | js | both   file type filter (default: auto)
      --workers  N       parallel workers (default: GOMAXPROCS)
      --src              read source bytes from stdin
```

```sh
capp-parse parse src/AppController.j
capp-parse parse Frameworks/
find . -name '*.j' | capp-parse parse
cat src/AppController.j | capp-parse parse --src --mode objj
```

Output is human-readable when stdout is a terminal; JSON per line otherwise.

Exit codes: `0` = OK, `2` = syntax errors found.

---

### debug

Walk a file or directory tree, stop at the first parse error, and display full diagnostic output: source context, parent node chain, and full concrete syntax tree. The failing file is opened in Xcode at the error line via `xed`.

This workflow is optimized for grammar and compiler development.

```
capp-parse debug [flags] <path>

Flags:
  -g, --grammar   path   explicit grammar dylib path, overrides search
  -m, --mode      auto | objj | js | both   file type filter (default: auto)
  -p, --profile          print per-file timing and aggregate summary
  -c, --context   N      source lines of context around error (default: 3)
      --no-xcode         suppress xed invocation
```

```sh
capp-parse debug Frameworks/AppKit
capp-parse debug --profile --no-xcode Frameworks/
capp-parse debug --context 5 src/AppController.j
```

Exit codes: `0` = all files OK, `2` = parse error found.

```sh

```

## Architecture note

`capp-parse` is designed as a fold-in seam for the `cappuccino` toolchain.
Its primary purpose is bootstrapping development of the compiler.
`cmd/parse/` and `cmd/debug/` wire directly into the parent toolchain's root command without modification. `cmd/root.go` and `cmd/version.go` are discarded when this happens.
